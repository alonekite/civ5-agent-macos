# Session and Match Identity Contract

Status: Bridge-session envelope implemented offline; match identity pending M5

## Purpose

Keep short-lived execution targeting separate from long-lived historical
grouping without claiming that Civ V exposes a verified permanent save ID.

## Bridge session identity

`bridge_session_id` is a lowercase canonical UUIDv4 generated by the component
that owns the live bridge connection. It is immutable for one connection-owner
lifetime and changes after watcher restart, reconnect, or `InGame` Lua-state
reselection.

It accompanies validated live observations and command requests/results at the
application boundary. M6 uses it with turn, active player, and live-state basis
to reject a plan created for another connection epoch.

It is not a save-file identifier and is not inferred from turn, player, map, or
other mutable game fields.

## Match identity

`match_id` is a lowercase canonical UUIDv4 created explicitly with an M5
journal. It is immutable for that journal and distinguishes one declared match
history from another.

Each journal begins with its initial bridge-session binding. A later connection
may join the same journal only through an explicit append-only
`session_binding` record containing the new `bridge_session_id`, capture time,
and binding authority. Automatic binding is prohibited until a stable
target-verified match fingerprint has its own versioned contract.

## Failure behavior

- Missing, malformed, or unexpected session identity fails closed for M6.
- A session mismatch makes a TurnPlan stale before any write.
- M5 rejects records from an unbound session.
- Ambiguous cross-session continuation never silently merges histories.
- Journal bindings never authorize M6 execution, retry, or recovery.

## Compatibility

Live-state schemas 2–5 do not contain this metadata. The watcher now emits and
brokers it beside the unchanged state payload, rejects missing or stale session
IDs before writes, rotates it for each connection epoch, and records it in the
M2 command audit. Direct commands create an identity for their one connection.
The journal `match_id` and `session_binding` records remain M5 work. Public
naming and compatibility are finalized in M7.
