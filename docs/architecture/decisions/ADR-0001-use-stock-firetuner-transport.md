# ADR-0001: Use stock FireTuner as the verified transport

Status: Accepted

Date: 2026-09-12

## Context

The App Store Campaign Edition discovers custom mods but forcibly hides the Mods
browser, so a normal custom Lua add-in cannot be enabled. Modifying a copied
signed application caused macOS integrity checks to reject it. The game ships a
FireTuner server that can evaluate Lua in its reported in-game state.

## Decision

Use the stock FireTuner protocol as the currently verified live transport.
Connect only to `127.0.0.1:4318`, perform the Firaxis handshake, select the
reported `InGame` state, and expose only code generated by internal allowlisted
operations. Keep the application bundle unchanged.

Because this build listens on `*:4318`, FireTuner must remain disabled outside a
bounded session protected by the macOS application firewall and an explicit
block-incoming rule for Civ V.

## Consequences

- The target Mac can support genuine bidirectional state and action experiments.
- Transport use requires strict session preflight and shutdown verification.
- FireTuner details remain behind the bridge boundary and must not leak into the
  eventual public API.
- Arbitrary caller-supplied Lua is prohibited.

## Alternatives considered

- `Modding.OpenUserData()`: retained as a fallback for a distribution that can
  enable custom mods; unavailable as the live primary path on this stock build.
- Modifying the signed application: rejected as unsafe and non-viable.
- Windows DLL approaches: incompatible with the target and out of scope.

## Supersedes

None.
